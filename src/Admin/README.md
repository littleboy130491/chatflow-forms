# Phase 1 administration

`AdminModule(FormRepository)` registers hooks only. The integrator must compose
it centrally; this lane does not change `Plugin.php`, Installer, dependency locks,
schema, build configuration, packaged assets, or `PLAN.md`.

## Features and contracts

- Forms: blank/Imajiner template creation, duplication, safe JSON export/import,
  trash, classic WordPress React builder and accessible dnd-kit reorder.
- Stable step/option IDs, historical key/value reservation, nested conditions,
  validation, groups, endings, design, per-form settings and phrase overrides.
- Ten-second autosave, bounded undo/redo via WordPress data, serialized saves and
  publish, 409 recovery, preservation of edits during in-flight requests, diff.
- Draft and block preview dynamically import the actual runtime library. Draft
  projection explicitly excludes private settings; media is resolved through
  WordPress attachment reads. Unsaved drafts use a synthetic preview-only ID,
  never a persisted/session ID. Default ending is passed in replay context.
  Preview is always `preview:true`, uses `unmount`/`getState`, and cancels stale
  mounts. The optional jump selector is absent unless the runtime provides it.
- Submissions: status tabs, filter/search parity, pagination, bulk read/star/spam/
  trash, escaped plain answers and frozen conversation replay, metadata/consent,
  private notes and actual delivery activity/retry contracts.
- Export: selected IDs/current filters and CSV options, queued progress, private
  owner-bound download. The actual server issues `admin-post.php?action=cff_download`
  with a ticket and export-specific nonce; the client restricts destination,
  uses same-origin credentials/no-store, and forbids redirects.
- Purge: exact formId/status/from/to/olderThanDays criteria (360-day default),
  preview token invalidation, literal DELETE confirmation, queued batch progress,
  purge audit. Global controls expose backend display/tracking/privacy/retention/
  proxy/spam/email/uninstall keys. Tools are separately capability-gated.
- Gutenberg `chatflow/form`: picker (manage_forms), numeric public ID fallback,
  inline/fullpage/height/theme, published runtime preview, server rendering solely
  delegated to `cff_render_form` supplied by Frontend.
- PHP MO/PO and three handle-named Jed catalogs under `src/Admin/languages` bundle
  438 reviewed Indonesian messages. Regenerate with
  `python3 src/Admin/languages/generate.py`; it rejects missing translations or
  mismatched sprintf placeholders and verifies the MO with GNU gettext.

Form files contain private configuration such as email recipients and webhook
URLs: protect them as administrative data. Signing secrets are blanked and
webhooks disabled on export. Imports always create a new server-validated draft.
Resume device-storage and consent disclosures are shown in form settings.
Uploads, MX lookups, scoring, CAPTCHA, launcher/popup/QR and analytics are not advertised as
implemented. No GitHub-token control/read/write exists.


The own unintegrated branch's `npm run typecheck` cannot resolve shared modules;

`style-submissions.css` and RTL counterparts, which PHP enqueues; its manifests
use core WP/React dependencies, not `wp-jsx-runtime`. Generated assets remain
outside this branch and must be regenerated by the integrator.

## Integration requirements / limits

Merge real shared/logic/backend/jobs/runtime lanes and compose the module. Build
runtime as a library exposing `mountRuntime`; retain its chunks or use proper
self-contained library entries. Pin jsdom directly (unit tests currently use the
locked transitive dependency). Include `src/Admin/languages` in release packaging.
Frontend must expose `cff_render_form`; REST/jobs must register the exact routes
used above, including draft email preview and published-only test delivery.

Unit component tests mock WordPress controls explicitly; logic is not mocked for
compile/build checks. No browser/GUI, integrated WordPress request flow, actual
email delivery, private filesystem downloads, multisite or caching-plugin
compatibility validation was performed in this lane. No PR was created.
